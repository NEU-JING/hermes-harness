# 探索引导指南

> Explore Agent 参考文档 — 帮助用户展开需求的引导问题

---

## 开场引导

当用户输入 `/explore` 但未指定具体主题时，用以下方式开场：

```
欢迎进入探索模式。这里是一个自由思考空间，不会创建任何文件。
我们可以：
1. 分析你的需求想法
2. 调研当前代码库
3. 对比不同技术方案
4. 绘制可视化图表帮助思考

你想从哪个开始？
```

---

## 需求探索引导

当用户给出模糊的需求时，通过以下问题帮助收敛：

### 基础问题

- "请描述你想做什么？"
- "这个功能解决了什么问题？"
- "预期的用户是谁？"
- "当前系统是怎么处理这个需求的？"

### 范围界定

- "哪些功能必须包含在本次范围内？"
- "哪些可以放到未来再做？"
- "这个变更会影响哪些现有模块？"

### 边界条件

- "什么情况下这个功能不应该工作？"
- "异常输入如何处理？"
- "有没有性能或安全方面的要求？"

---

## 代码库调研引导

当用户需要了解当前代码库时：

### 项目结构

- "需要我查看项目的整体目录结构吗？"
- "关注哪个模块或服务的具体实现？"

### 现有实现

- "需要查找现有的类似功能？"
- "需要检查某个 API 的当前行为？"
- "需要查看现有的数据模型？"

### 依赖分析

- "需要分析模块之间的依赖关系？"
- "需要查看某个关键依赖的版本和用法？"

---

## 方案对比引导

当用户需要对比多个方案时，输出结构化的对比表：

```
| 维度 | 方案 A | 方案 B | 方案 C |
|------|--------|--------|--------|
| 复杂度 | ⭐⭐ | ⭐⭐⭐ | ⭐⭐⭐⭐ |
| 实现成本 | 2天 | 5天 | 8天 |
| 可维护性 | 高 | 中 | 高 |
| 风险 | 低 | 中 | 低 |
```

### 推荐格式

1. 列出每个方案的 **核心思路**
2. 对比 **优缺点**
3. 给出 **推荐方案** 及 **理由**

---

## 探索结束引导

当探索内容足够明确时：

```
看起来我们已经有了比较清晰的方向。接下来你可以：

1. 说 "进入开发" → 进入 SDD 正式流程（探索发现可选作为 PRD 输入）
2. 说 "放弃" → 退出探索模式，不留任何痕迹
3. 继续深入某个方向 → 告诉我你想进一步探索什么
```

---

## 注意事项

- 不创建任何文件或目录
- 不修改项目中的任何现有文件
- 探索对话历史在退出后不保留
- 如果用户选择进入 SDD，探索摘要以可选方式传递给 PO Agent
